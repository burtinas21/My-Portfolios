# Project Structure

## Overview

This is a monorepo containing a backend API (Laravel) and frontend SPA (Vue.js) for a portfolio application.

```
my-app/
├── backend/              # Laravel API backend
├── frontend/             # Vue.js frontend application
└── .kiro/                # Kiro workspace configuration
```

### Key Backend Patterns

**Controllers:**
- Separate controllers for Admin (authenticated) and Api (public) routes
- Thin controllers following single responsibility principle
- Validation handled in controller or request classes

**Models:**
- Eloquent ORM models with relationships defined
- Mass assignment guarded properties
- Model factories for testing

**Authorization:**
- Policies in `app/Policies/` enforce access control
- User model uses Laravel's authorize middleware

**API Routes:**
- Prefix: `/api/` for all endpoints
- Admin routes: `/api/admin/*` (require authentication)
- Public routes: `/api/*` (read-only, rate-limited)

### Key Frontend Patterns

**Routing:**
- Client-side routing with Vue Router
- Public routes (anyone can access)
- Admin routes (require authentication)
- Route guards for protected areas

**State Management:**
- Pinia stores for global state
- Separate stores per domain (auth, projects, etc.)
- Async actions for API calls

**Components:**
- Organized by scope: admin, public, common
- Props for input, events for output
- Composition API with `<script setup>`

**API Integration:**
- Axios instance configured in `src/api/http.js`
- Interceptors for authentication tokens
- Error handling and response formatting

**Styling:**
- Tailwind CSS for utility-first styling
- Dark/light theme support (configured in stores)
- Global styles in `src/assets/styles/`

## Development Workflow

### Local Development Setup

1. **Backend:**
   ```bash
   cd backend
   composer setup  # Installs deps, generates key, runs migrations
   composer run dev
   ```
   Backend available at `http://localhost:8000`

2. **Frontend:**
   ```bash
   cd frontend
   npm install
   npm run dev
   ```
   Frontend available at `http://localhost:5173`

### File Modification Conventions

**Backend:**
- PHP files follow PSR-12 standard (enforced by Pint)
- Migrations use timestamps for ordering
- Model methods use camelCase
- Controller methods follow RESTful naming

**Frontend:**
- Vue files use PascalCase for component names
- Stores use camelCase for state properties
- CSS classes use kebab-case (Tailwind)
- Composables prefixed with `use` (e.g., `useAuth`)

## Important Notes

- Backend and frontend are independent deployables
- Both have their own `.env` configuration
- Database migrations are version-controlled in `backend/database/migrations/`
- Frontend is a static SPA built from `frontend/src/`
- No server-side rendering (SSR) needed
- API documentation in `backend/API.md`
